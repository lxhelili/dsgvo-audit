### ai-chatbot-processor — without skill

- **A dedicated DSE module for the KI-Funktion is required and its contents listed (provider, …** — This assertion bundles six distinct required content items into one pass/fail judgment. - **The response notes that tax-related chat input can carry special-category data ... marked …** — 'marked as a rule' is not defined anywhere the executor could see, and is easy to satisfy by accident or fail by phrasing alone even when the substantive legal analysis is correct (as here). Consider giving the eval an explicit example of the expected framing (e.g. 'as a conservative rule, treat any Kirchensteuer/Behinderung-adjacent input as Art. 9 data even where legally debatable') so graders and skills converge on the same bar.
- **OpenAI is classified as an Auftragsverarbeiter (Art. 28) with the four checks named…** — The assertion's phrasing implies checking for the literal term 'Auftragsverarbeiter', but responses can (and this one did) satisfy the substance via 'AVV nach Art. 28' / 'DPA (Art. 28)' without ever using that exact noun. Worth clarifying whether the assertion is testing terminology or substance, since strict graders could reasonably disagree.
- No assertion covers § 203 StGB / § 62a StBerG (Steuerberater professional secrecy), even though the prompt is specifically about a Steuerberatung and this is arguably the single most consequential domain-specific finding (it requires a written confidentiality undertaking from OpenAI/Supabase that an ordinary Art. 28 DPA does not satisfy). - **The response ends with the RDG disclaimer and does not call the setup 'konform' without co…** — In the transcript, the RDG disclaimer is followed by a plain source-link list, so it is not literally the final line of the response. The eval should clarify whether trailing citation lists are exempt from the 'ends with' requirement, to avoid inconsistent grading between runs that append sources and runs that don't.

_This baseline (without_skill) response is unusually strong for a no-skill run: it read all four source files, ran two targeted WebSearches to check time-sensitive facts instead of asserting from memory, and correctly surfaced a domain-specific issue (§ 62a StBerG professional secrecy) that none of the 9 assertions even test for.
