- **Every concrete OpenAI retention or residency fact (e.g. 30-day abuse-monitoring logs, eu.a…** — Read strictly: any OpenAI retention/residency fact (incl. short forms like 'EU-Datenresidenz wählbar') must carry a dated source or a verify mark on that fact; code-derived facts ('Standard-Endpunkt, keine EU-Residenz konfiguriert') and recommendations were not counted. Consider saying explicitly whether bare 'EU residency available' counts, since it decided two runs.
- **Any statement about the DPF status of OpenAI or Supabase is either absent (replaced by 've…** — Read literally: relaying a secondary site's DPF status to the client (even flagged 'kein Beleg' and with both branches) counts as a statement about DPF status not taken from the official list, so it fails. If the intent is only 'no verdict', reword; otherwise the current wording is right.
- **The KI-Funktion is covered in the Datenschutzerklärung either by a delivered draft module …** — Read as: a delivered module, or one explicit list containing all six items (provider, purpose, data categories, retention, third-country transfer, Art.-22 statement); pointing to a template module number or another finding does not count. Consider also checking that a delivered module does not assert unverified facts (old_skill run-2's draft states 'Verarbeitung erfolgt in der EU' and '§ 62a verpflichtet' as present facts, gated only by a 'vor Veröffentlichung prüfen' note).
- **(missing)…** — No assertion checks the API-hardening finding (client can inject role 'system', no validation/rate limit), which all four runs found; also none checks that the Art. 50 label is shown before the first message. Both are cheap to add but would not discriminate here.

_All four runs catch the core issues (Art. 50 KI-VO with label text, § 203 Abs. 1 Nr. 3 StGB + § 62a StBerG, Art. 22 triage, unlimited chat_logs with 30-day pg_cron, localStorage under § 25, Art.-9 via Kirchensteuer/Behinderung with conservative rule, RDG disclaimer in chat). What separates them is sourcing discipline: both with_skill runs fetched the OpenAI 'your data' page and cite every retention/residency fact with a dated evidence ID (E-13/E-14, 25.09.2026; re-fetched by the grader and confirmed: no training since 01.03.2023, abuse logs up to 30 days, ZDR by prior approval, non-US residency requires abuse-monitoring-controls approval + Modified Retention amendment). Both old_skill runs did not fetch vendor docs and state 'EU-Datenresidenz wählbar/optional' plainly in the processor table, covered only by a generic footnote. old_skill run-1 additionally relays a secondary-site DPF status ('Sekundärquelle nennt OpenAI als nicht gelistet', companyscope.io) in the chat answer. with_skill run-1 fails the DSE-module assertion (its item list omits purpose and data categories and it defers the module text). The assertions capture these differences well; the OpenAI-facts assertion is the most discriminating one._
