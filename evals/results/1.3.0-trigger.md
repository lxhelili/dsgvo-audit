## Harness setup (both needed for a valid run)

1. **Isolate from installed copies.** A machine with the plugin installed (or an older `datenschutz-review` skill in `~/.claude/skills`) offers the model a second, near-identical skill; it picks that one and the run counts as a miss. `claude -p … --setting-sources project` loads neither user skills nor user-enabled plugins.
2. **One project root per query.** Stock `run_eval.py` writes every worker's temporary command into the same `.claude/commands/`, so with parallel workers each `claude -p` sees up to 10 identically-described `dsgvo-audit-skill-<uuid>` commands, picks another worker's, and the run is scored as not triggered. The first run of this iteration hit exactly that: 3/36 positives, 24/24 negatives — a pattern that looks like a weak description but is a harness artefact. Fix: `tempfile.mkdtemp()` as the project root inside `run_single_query` (plus `stdin=subprocess.DEVNULL` to skip the 3 s stdin wait).
